# セキュリティ診断 総合評価

| 項目 | 内容 |
|---|---|
| 検査日 | 2026-10-31 |
| 対象 | YUZURIHA テーマ（WordPress オリジナルテーマ）`main` / `afbf227` |
| 方法 | ソースコードの精読（読み取りのみ）、隔離した Docker 環境での統合テスト・HTTP テスト・プロパティベーステスト、修正案の検証 |
| 検査しなかった対象 | 本番・ステージング（URL と許可範囲が未指定のため、外部ホストへは一切アクセスしていない）、テーマ外のプラグイン |

## 結論

**重大（Critical / High）な脆弱性は見つからなかった。** テーマには独自の REST API・Ajax・フォーム処理・SQL・ファイル処理・外部通信がない。そのため、認証の回避、権限昇格、SQL インジェクション、CSRF、SSRF、コード実行につながる経路は存在しない。寄稿者が入力できる値（カスタムフィールド・ブロック属性）による XSS も、攻撃文字列とランダム入力で試して不成立だった。

一方で、**WordPress 本体が「非公開」と判断している情報を、テーマの出力が別の経路で公開してしまう欠陥が 4 件**あり、すべて隔離環境で再現した（いずれも Medium、CVSS 5.3）。

| ID | 内容 | 必要な権限 | 状態 |
|---|---|---|---|
| F-01 | 記事のない利用者（会員など）の筆者ページで、自己紹介・サイト URL・ログイン名由来のスラッグが公開される。ID を順に指定すれば全員分を集められる | なし | CONFIRMED |
| F-02 | パスワード保護した投稿のアイキャッチ（HTML・OGP・JSON-LD）、インタビュー一覧のバイライン・本文の長さが、パスワードなしで見える | なし | CONFIRMED |
| F-03 | 公開ページのパンくず（JSON-LD）に、非公開・下書きの親ページのタイトルと ID が出る | なし | CONFIRMED |
| F-04 | テーマをリポジトリのまま配置すると、`.git/`・`.agents/`（**本報告書を含む**）・`AGENTS.md` が Web から読める | なし（配置方法に依存） | CONFIRMED |

4 件とも小さな修正で解消でき、修正案（[security-tests/proposed-fix.patch](security-tests/proposed-fix.patch)）を当てたコピーで、再現テストがすべて成功した。公開記事のアイキャッチ、記事のある投稿者のページ、公開の親ページ、CSS・JS の配信は従来どおり残ることも、対照テストで確認した。

**対応状況（2026-10-31 更新）:** 承認を受けて、ブランチ `fix/security-2026-10-31` で F-01〜F-04 を修正した（**未マージ**）。隔離環境での再検証は、HTTP が 17 成功・0 失敗、統合が 10 成功・0 失敗だった（`security-tests/results/fix-branch/`）。テーマの回帰テストは 73 件すべて成功（F-01〜F-04 の 6 件を追加）。本番に反映されるまでは、下の「最優先の対応」1 が引き続き必要。

## 最優先の対応

1. **本番のテーマディレクトリに `.git/`・`.agents/`・`AGENTS.md`・`tests/` がないか、すぐに確認する。** 置かれている場合は削除する。本報告書は未修正の脆弱性の再現手順を含むため、修正の反映までは特に公開してはならない。
2. 修正案を専用ブランチで反映し、F-01〜F-04 を解消する（[remediation-plan.md](remediation-plan.md)）。

## 良好だった点

- 出力のエスケープが一貫している（`esc_html`・`esc_attr`・`esc_url`・`wp_kses_post`、JSON-LD の `JSON_HEX_TAG | JSON_HEX_AMP`）
- URL パラメータ（`?order`）は型を確認してから許可リストで正規化している
- カスタマイザーの権限: SNS は管理者、GTM は `unfiltered_html` を持つ管理者だけが保存できる（変更セット経由も含めて実測）
- XML-RPC は `system.*` 以外のメソッドがなく、`multicall` による総当たりの増幅もできない。コメント投稿は REST・フォームとも拒否される
- テーマの PHP ファイルと `tests/` は、直接アクセスしても何も実行しない
- 2026-10-17 の監査で見つかった項目（BUG-001〜028）の修正は、今回の範囲で後退していない

## 参考情報（WordPress 本体の仕様・強化策）

REST API の応答にテーマのセキュリティヘッダーが付かない（I-01）。停止前からあるコメントが REST で読める（I-02）。記事のある利用者は REST で列挙できる（I-03）。CSP がない（I-04）。GTM のコンテナが外部の信頼境界になる（I-05）。いずれもテーマの不具合ではなく、サイトの方針に合わせて対応を判断する（[findings.md](findings.md)）。

## 検査の限界

本番の WordPress 本体・プラグイン・PHP・Web サーバーのバージョンと設定は確認していない。そのため、既知 CVE の照合は行っていない。ログインした状態の HTTP テストと、マルチサイト・Nginx での確認も未実施である（[coverage-matrix.md](coverage-matrix.md)）。
