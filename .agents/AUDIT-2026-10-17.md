### システム構造の要点

- PHP 7.0+ / WordPress 6.3+ 想定のクラシックテーマ（Block API v3 を採用したため、2026-10-17 に 5.8 から引き上げた）。
- 外部リソースは CDN の Swiper 11.0.5 だけで、既定では読み込まない。Google Fonts は廃止し、`fonts/` 内のフォントを使う。
- テーマ自身は、フォーム処理・AJAX・REST ルート・WP-Cron・DB 書き込み・ファイルアップロードを持たない。
- 入力経路は次に限られる。
  - `$_GET['order']`（インタビュー一覧の並び順）
  - 編集者が入力する投稿本文・ブロック属性・カスタムフィールド・カスタマイザー値
  - 404 ページの URL とリファラー（クライアント側で計測用に送信）
- このため、監査プロンプト §5（状態遷移・同時実行）と §6（部分障害）の対象になる処理はない。

## 1.4 一部対応の不具合（詳細）

### BUG-027 フォントとエディター用 CSS の重さ

- 重要度: Informational ／ 確度: Confirmed ／ カテゴリー: 性能
- 対象: `fonts/`、`css/page/interview*.css`、`inc/assets.php`（`editor_style`）
- 根拠:
  - 使用中のフォントは `SourceHanSansJP-VF.otf.woff2`（約 4.1MB）と `NotoSerifJP-VariableFont_wght.woff2`（約 5.9MB）。どちらもサブセット化していない。
  - ブロックエディター用のスタイルに、表側の `interview.css` をそのまま登録している。
- 判断・対応状況:
  - **未使用フォントの同梱はリスク受容。** 案件ごとに使うフォントが異なるため、ベーステーマとして複数のフォントを同梱する方針である。ブラウザが読み込むのは CSS で使っているフォントだけなので、閲覧時の転送量には影響しない（配布物のサイズが大きくなるだけ）。
  - **Google Fonts は廃止済み。** 外部への送信と外部依存をなくした。
  - **エディターへの影響は軽減済み。** Block API v3（BUG-028）でエディターが iframe 化されるため、表側 CSS のグローバル指定（`*`、`html`）は iframe の中だけに効く。

## 1.6 テストカバレッジ上の不足

- テストは `tests/run.php`（WordPress 関数のスタブ上で動く 53 件）だけである。PHPUnit、WordPress 統合テスト、E2E はない。スタブは実際の関数を簡略化したものなので、**実環境での確認が別途必要**。

## 1.8 末尾スラッシュの統一（BUG-025）の運用メモ

- テーマが生成する一覧ページの URL（インタビュー一覧の canonical と、一覧ページの `og:url`）は、末尾スラッシュなしで統一している。例: `https://example.com/interviews`、`https://example.com/interviews/page/2`。
- WordPress は、パーマリンク構造の末尾にスラッシュがあると、スラッシュなしの URL を付きの URL へ 301 リダイレクトする（`redirect_canonical()`）。そのままでは、canonical がリダイレクト元を指す矛盾した状態になる。
- **設定 → パーマリンクで、末尾スラッシュのない構造（例: `/%postname%`）を選ぶこと。** こうすれば WordPress 自身が出力するリンク（`get_permalink()`、アーカイブリンク、ページ送り）もスラッシュなしになり、サイト全体の URL が揃う。
- 既存サイトで構造を変える場合は、旧 URL からのリダイレクトと Search Console の再登録を計画する。

## 1.9 BUG-006（HSTS）の運用メモ

| 条件 | 送信される値 |
|---|---|
| HTTP | 送信しない |
| HTTPS・既定値 | `max-age=31536000` |
| `includeSubDomains` を true | `max-age=31536000; includeSubDomains` |
| `includeSubDomains` と `preload` を true | `max-age=31536000; includeSubDomains; preload` |
| `preload` だけを true | `max-age=31536000`（`preload` は付けない） |
| フィルターが `false` を返す | 送信しない |
| `max-age` を 0 | `max-age=0`（ブラウザに記憶された設定を破棄させる） |

1. 可能なら Web サーバーや CDN で設定し、テーマ側はフィルターで `false` を返して送信を止める。テーマの `send_headers` は、管理画面・静的ファイル・`wp-login.php` には効かない。
2. 新規に有効化するときは、`max-age` を段階的に延ばす（300 秒 → 1 週間 → 1 か月 → 1 年）。
3. 旧設定（2 年・`includeSubDomains`・`preload`）を配信済みのサイトでは、`max-age=0` を一定期間送る。プリロードリストに登録済みであれば、hstspreload.org で削除を申請する。
