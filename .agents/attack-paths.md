# 攻撃経路と影響分析（attack paths）

検査日: 2026-10-31。各経路は隔離環境でダミーデータを使って再現した。本番での被害は実証していない。

## AP-1 会員プロフィールの一括収集（F-01 → I-03）

| 項目 | 内容 |
|---|---|
| 必要な攻撃者権限 | なし |
| 入口 | `GET /?author=1`, `/?author=2`, … |
| 原因となるコード | `inc/seo.php:820-845`、`inc/seo.php:241-278`、`archive.php:13` |
| 破られたセキュリティ境界 | 「記事を公開した人だけが筆者として公開される」という WordPress の公開範囲（`/wp/v2/users` は記事のある利用者だけを返す）を、テーマの筆者ページが広げている |
| 影響を受けるデータ | 全利用者のスラッグ（既定ではログイン名）、表示名、自己紹介、サイト URL。会員サイトでは顧客の氏名・所属などが入り得る |
| 想定される被害 | 個人情報の収集、ログイン名の判明によるパスワード攻撃の効率化（XML-RPC は停止済みだが `wp-login.php` は残る）、標的型フィッシング |
| 類似処理 | `single.php:43-44` の著者ボックス（記事のある投稿者だけなので問題なし）、`/wp/v2/users`（本体。記事のある利用者のみ） |
| 根本的な修正 | 記事のない投稿者アーカイブを 404 にする（`template_redirect`）。JSON-LD はページの存在を前提に出す |

```
攻撃者 ──GET /?author=N (N=1..)──▶ archive.php（200）
                                   ├─ <h1>Author: 表示名</h1> + 自己紹介（the_archive_description）
                                   └─ <script type="application/ld+json"> Person{name, description, url=/author/{login}, sameAs}
```

## AP-2 パスワード保護した記事の内容の推測（F-02）

| 項目 | 内容 |
|---|---|
| 必要な攻撃者権限 | なし（パスワードを知らない） |
| 入口 | 保護された投稿の URL、`/interview`、SNS のリンクプレビュー（og:image を取得するクローラー） |
| 原因となるコード | `inc/seo.php:336-343`・`1166`、各テンプレートのアイキャッチ、`archive-interview.php:127-150`・`188`・`333` |
| 破られたセキュリティ境界 | パスワード保護（本体は本文と抜粋を隠すが、付随情報の扱いはテーマに任されている） |
| 影響を受けるデータ | アイキャッチ画像（URL と画像そのもの）、インタビュー相手の氏名・肩書き（バイライン）、本文の長さ |
| 想定される被害 | 限定公開のインタビュー（公開前の取材・社内向け記事など）の相手が誰かが分かる。アイキャッチに写った人物・資料が見える。SNS で URL が共有されると、プレビューに画像が出る |
| 類似処理 | `single-interview.php`（保護済み。BUG-007 で修正）、JSON-LD の説明文（保護済み）、`og:description`（保護済み） |
| 根本的な修正 | 「保護中は付随情報を出さない」を共通の規則にし、アイキャッチ・カスタムフィールド・本文由来の値を出すすべての箇所で `post_password_required()` を確認する |

## AP-3 非公開ページの存在・タイトルの把握（F-03）

| 項目 | 内容 |
|---|---|
| 必要な攻撃者権限 | なし |
| 入口 | 親ページが非公開・下書きの公開ページ |
| 原因となるコード | `inc/seo.php:1031-1034` |
| 破られたセキュリティ境界 | 投稿ステータス（非公開・下書きは、権限のない人には存在しない扱い） |
| 影響を受けるデータ | 非公開・下書きの親ページのタイトルと投稿 ID |
| 想定される被害 | 公開前の企画名・キャンペーン名、社内向けページの存在の把握。ID から他の非公開コンテンツを推測する手がかり |
| 類似処理 | タームの親（`inc/seo.php:1040-1046`。タームに非公開の状態はないため該当なし）、投稿ページ（`page_for_posts`。公開設定のページが前提） |
| 根本的な修正 | パンくずに入れる祖先を `is_post_publicly_viewable()` で絞る |

## AP-4 開発用ファイル・履歴の取得（F-04）→ 他の脆弱性の発見

| 項目 | 内容 |
|---|---|
| 必要な攻撃者権限 | なし |
| 前提 | テーマをリポジトリのまま（`git clone` / `git pull`、またはフォルダごとアップロード）配置している |
| 入口 | `/wp-content/themes/{テーマ}/.git/HEAD` などを取得し、公開されている Git 用ツールで復元する |
| 原因 | テーマに配信を拒否する設定がない。README の除外手順に依存している |
| 破られたセキュリティ境界 | 「ソースとドキュメントは公開しない」という運用上の境界 |
| 影響を受けるデータ | テーマの全ソース・コミット履歴、監査レポート、**本報告書**（未修正の脆弱性と再現手順）、指示ログ |
| 想定される被害 | 未修正の脆弱性（F-01〜F-03）の悪用の手引きになる。履歴に秘密情報がないことは確認したが、今後コミットされた場合も同様に漏れる |
| 根本的な修正 | 配布物から除外する（`.gitattributes` の `export-ignore` と `git archive`）。テーマの `.htaccess` とサーバー設定で、ドットファイルと開発用ディレクトリを拒否する |

## 組み合わせ（複数の正規操作による不正な状態。仮説 8）

| 組み合わせ | 結果 |
|---|---|
| F-04 → F-01〜F-03 | `.agents/findings.md` を読めば、修正前のサイトで再現手順をそのまま実行できる。**修正を本番に反映するまで、`.agents/` を本番に置かないことが特に重要** |
| 親ページを非公開に変更 → 子ページは公開のまま（F-03） | 編集者の通常の操作だけで発生する。親を非公開にした時点で、子ページのパンくずから親のタイトルが出る |
| 記事を公開した投稿者 → 全記事を非公開・削除（F-01） | その投稿者も記事のない利用者になり、プロフィールが F-01 の経路で出続ける |
| 寄稿者の入力（E-09, E-10） → 管理者がプレビュー・公開 | 出力時のエスケープで XSS は成立しない（統合・HTTP テストで確認）。管理者の権限で任意のスクリプトが動く経路はない |
| GTM コード（管理者） → GTM アカウントの乗っ取り | テーマの外の境界。GTM のコンテナを書き換えられると、全ページで任意のスクリプトが動く（I-05） |

## 影響範囲のまとめ

- 改ざん・権限昇格・コード実行・DB への不正アクセスにつながる経路は見つからなかった。テーマに独自の書き込み系エンドポイント、SQL、ファイル処理、外部通信がないため。
- 4 件はいずれも機密性（Low）への影響で、主な被害は個人情報と限定公開コンテンツの露出。
- F-04 だけは配置方法に依存し、該当する場合は他の 3 件の発見を容易にする。そのため優先度を上げている（[remediation-plan.md](remediation-plan.md)）。
